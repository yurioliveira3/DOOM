# docs/notes

Notas de planejamento e ideias de estudo sobre este fork do DOOM —
porte para macOS, exercícios de aprendizado, melhorias no core, etc.
Nada aqui é definitivo: um documento pode ser só um brainstorm sem
compromisso de execução, ou um plano em andamento — o campo `Status:`
no topo de cada arquivo diz qual é qual.

## Como a pasta é organizada

- Cada assunto vive em um arquivo próprio, nomeado só pelo tema
  (`porte-macos.md`, `ideia-astar.md`, etc.) — sem número no nome.
- A ordem/prioridade entre os documentos vive em **[INDICE.md](INDICE.md)**,
  não no nome do arquivo. Isso evita ter que renomear arquivo toda vez
  que a prioridade muda.
- Quando uma ideia vira trabalho de verdade, ela ganha uma branch
  própria (não misturar com `port/macos-build`) e pode virar um
  documento mais detalhado — continua sem número no nome.

## Convenções dos documentos

- Começar com `Status:` (ex.: "planejamento", "ideia — sem plano de
  execução").
- Manter uma seção de histórico/atualizações quando o documento for
  um plano ativo, pra registrar decisões tomadas ao longo do tempo.
- Atualizar o `INDICE.md` sempre que a prioridade mudar ou um novo
  documento for adicionado.
